# 首页组件显隐与无空洞布局设计

## 背景

TO-DO Panel 首页当前固定包含音乐、番茄钟、快速录音、当前窗口、镜子、随笔记和常用指令七个组件。用户可以长按换位，也可以在迷你、小、中、大四档之间调整尺寸，但不能隐藏自己不需要的组件。

现有首页采用 `12 × 4` Bento 网格。七个组件的默认占位面积合计正好为 48 格，因此直接给组件增加 `hidden` 会留下空洞。新增显隐能力必须把“隐藏组件”和“重新求解剩余组件布局”视为同一事务，不能只修改可见性。

## 目标

- 用户可以在设置页单独隐藏或恢复任意首页组件。
- 首页始终至少保留一个可见组件。
- 任意非空显隐组合都完整覆盖 `12 × 4` 网格，不留空白、不重叠、不越界。
- 隐藏不会删除组件数据，也不会覆盖原有顺序和尺寸偏好。
- 剩余组件可以临时放大，但组件内部的文字、图片、按钮和列表不得拉伸、重叠、遮挡或异常变形。
- 恢复组件后重新参与自适应布局，并继续使用此前保存的顺序与尺寸偏好。
- 现有镜子、录音与动效的资源释放约束继续成立。

这里的“不留空白”指不存在未被组件占用的逻辑网格单元；现有组件之间统一的 12px 设计间距和组件内部必要留白继续保留，但间距不得因隐藏数量变化而扩大成空洞。

## 非目标

- 不允许用户创建新组件或安装第三方组件。
- 不提供任意拖拽调整组件边界的自由画布。
- 不改变首页固定的 `12 × 4` 逻辑网格和展开内容区尺寸。
- 不借此重构其他 Tab、主进程窗口状态机或 LocalStorage 既有数据结构。
- 不在本功能中处理剪贴板、自动更新、录音兼容或窗口展开性能等其他反馈项。

## 非功能目标

- **响应性**：显隐事务本身（不含 460ms Auto Layout 视觉动效）在目标 Apple Silicon Mac 上 p95 小于 16ms，100 次连续操作不得出现超过 50ms 的长任务。
- **功耗**：隐藏音乐后活动 WebGL RAF 数为 0；隐藏当前窗口后窗口枚举 IPC 数为 0；重排动效不使用模糊或动态大阴影，真实组件及其内部内容不做几何缩放。
- **可靠性**：显隐操作对组件业务数据的 RPO 为 0；无效候选布局完整回滚；存储失败不伪装成已持久化成功。
- **可访问性**：七个开关可通过键盘操作并有明确名称；隐藏组件及尺寸按钮不可聚焦；失败和降级通过现有 `role="status"` 区域播报；焦点不得落在被隐藏 DOM 内。
- **可维护性**：模板、验证器和状态 reducer 为无 Electron 依赖的纯函数；新增组件前必须显式更新注册表、模板策略和测试矩阵。

## 核心设计原则

### 0. 从用户问题反推不可破坏的不变量

“隐藏首页组件”不是删除组件，也不是单纯把 DOM 设为不可见。一次操作只有同时满足以下条件才算成功：

1. **意图成立**：开关、当前会话状态、持久化状态和首页最终呈现表达同一个显隐结果。
2. **空间完整**：至少一个组件可见，且最终布局的 48 个逻辑格每格恰好被覆盖一次。
3. **内容完整**：组件容器变化不能通过缩放内容实现；主要控件不得重叠、越界、失焦或不可操作。
4. **数据无损**：显隐操作不得修改组件业务数据、保存顺序和尺寸偏好。
5. **资源正确**：隐藏镜子立即释放摄像头；隐藏纯视觉组件后停止无意义的动画或扫描；具有业务语义的番茄钟继续计时。
6. **事务一致**：校验或布局失败时，DOM、内存状态和 LocalStorage 都保持操作前状态；存储失败是唯一允许的降级，此时明确提示“仅当前会话生效”。
7. **操作幂等**：请求的绝对显隐值已经满足时返回成功但不重排、不写盘、不发事件，也不触发与状态迁移相关的资源守卫。

这七条是不依赖具体实现的验收准绳。任何动画、模板或设置页样式与它们冲突时，以这些不变量为准。

### 1. 可见性、顺序、尺寸三种状态彼此独立

首页继续使用既有顺序键 `notch-home-order-v3` 和尺寸键 `notch-home-widget-sizes-v2`。新增：

```text
notch-home-hidden-modules-v1
```

该键保存显式隐藏的组件 ID 数组，例如：

```json
["mirror", "recorder"]
```

保存“隐藏列表”而不是“可见列表”，可以让未来新增的组件默认显示，同时避免复制顺序信息。有效组件 ID 固定为：

```text
music, pomodoro, recorder, windows, mirror, note, commands
```

读取时丢弃未知 ID、去重并按上面的固定注册表顺序规范化。注册表顺序只保证序列化稳定，不跟随用户可编辑的 `notch-home-order-v3` 变化。若存储损坏、不是数组或导致七个组件全部隐藏，则回退为空数组，即恢复全部组件。只要原始值与规范值不同，就尝试把规范值写回；修复写入失败时标记为“仅当前会话”，不能让设置页误报已持久化。关闭最后一个可见组件时拒绝写入，保留原状态并提示“首页至少保留一个组件”。

### 2. 偏好尺寸不等于临时实际占位

`mini / small / medium / large` 是用户长期保存的尺寸偏好。显隐变化后，布局引擎可以给组件分配不同的临时实际占位，但不得把临时结果写回尺寸偏好。

组件 DOM 同时保留两个概念：

- `data-widget-size`：用户保存的尺寸偏好。
- `data-layout-variant`：根据本次实际矩形推导出的内部响应式版式。

这样隐藏镜子导致随笔记临时变大时，不会把随笔记的偏好永久改成 `large`；镜子恢复后，原始偏好仍然有效。

首页存在两种互斥的布局模式：

- 七个组件全部可见时是“偏好尺寸模式”，保留现有尺寸切换能力。
- 只要有组件隐藏就是“自动填充模式”，实际矩形完全由有限模板决定，所有组件的尺寸切换按钮隐藏且不可聚焦。

自动填充模式不接受尺寸修改，避免用户点击后没有视觉结果，也避免调整某个可见组件时，现有容量归一化算法暗中改变隐藏组件的尺寸偏好。恢复全部七个组件后，原尺寸偏好原样继续生效。

### 3. 使用有限模板保证零空洞

组件只有七个，可见数量只有 1～7 七种。与其使用结果难以预测的通用 Masonry 算法，不如使用经过穷举验证的有限模板。所有坐标均以左上角为原点，格式为 `{ column, row, width, height }`。

| 可见数 | 模板 |
| --- | --- |
| 1 | 一个 `12 × 4` 全幅组件 |
| 2 | 两个 `6 × 4` 组件左右平分 |
| 3 | 三个 `4 × 4` 组件横向排列 |
| 4 | 四个 `6 × 2` 组件组成 `2 × 2` |
| 5 | 偏好尺寸最大的组件占左侧 `4 × 4`；其余四个在右侧组成 `2 × 2`，每个 `4 × 2` |
| 6 | 六个 `4 × 2` 组件组成 `3 × 2` |
| 7 | 继续使用现有 `packHomeWidgetLayout()`，保持完整 Bento 的尺寸偏好能力 |

五组件模板的主组件按 `large > medium > small > mini` 选择；同档时取 `notch-home-order-v3` 中更靠前的组件。该选择只影响本次空间分配，不修改保存顺序。

所有模板必须满足：矩形面积合计为 48；每个格子恰好被覆盖一次；不存在负坐标、越界或交叠。布局函数和布局验证器都是 `renderer/domain.js` 中的纯函数。渲染层必须先验证完整结果，再一次性写入 DOM，不允许边求解边渲染，也不允许自行修补空洞。

## 组件内部响应式设计

外层网格只改变组件容器的矩形，不使用 `transform: scale()` 拉伸组件内容。根据实际占位推导以下版式：

| 版式 | 典型占位 | 内部行为 |
| --- | --- | --- |
| `mini` | `2 × 1` | 最少信息和主要动作，隐藏非关键预览 |
| `compact` | `2 × 2` | 紧凑纵向结构，固定控件尺寸 |
| `wide` | `4 × 2`、`6 × 2` | 横向排布，正文或列表占剩余宽度 |
| `tall` | `4 × 4` | 纵向完整结构，列表和正文可滚动 |
| `full` | `6 × 4`、`12 × 4` | 完整结构，增加内容容量而不是放大字体和按钮 |

具体约束：

- 音乐、番茄钟根据容器宽高切换紧凑、横向和完整结构；播放按钮与计时控件保持固定比例。
- 快速录音的开始、暂停、停止按钮不得缩放；空间不足时优先减少转写预览，不能覆盖控制区。
- 当前窗口和常用指令根据宽度调整列数或可见条数，溢出内容在组件内部滚动。
- 随笔记的工具栏保持可操作，正文占据剩余空间并在内部滚动。
- 镜子始终使用 `object-fit: cover` 填充实际容器，不对图像做非等比拉伸。
- 所有组件外层设置 `min-width: 0; min-height: 0; overflow: hidden`，滚动只发生在明确的内容容器中。

内部版式优先使用 CSS 容器查询或 `data-layout-variant` 精确选择器，禁止依赖整个窗口宽度猜测单个组件尺寸。

## 重排动效

原始 `applyHomeLayout(true)` 直接在真实组件上执行包含 `scaleX/scaleY` 的 FLIP。当组件宽高发生变化时，它会短暂拉伸内部文字、图片和控件；完全移除 FLIP 又会损失用户已经习惯的 Auto Layout 连续感。两者需要拆层处理。

显隐操作不在旧布局上等待淡出。等待动画后再提交状态会引入快速连点丢更新、录音状态竞态和摄像头延迟释放，因此状态与资源仍先同步提交，动画只负责提交后的视觉衔接。

显隐变化采用以下事务顺序：

1. 根据**当前最新状态**计算候选隐藏集合。
2. 求解并完整验证候选布局；失败则不产生任何状态或 DOM 变化。
3. 若隐藏镜子，立即释放摄像头和镜面动画资源。
4. 在同一个 JavaScript 任务内提交内存状态并原子更新全部组件矩形。
5. 同步写入 LocalStorage，随后派发状态事件。
6. 从提交前矩形创建不含子元素、不可交互的临时卡片外壳；外壳用 460ms `translate + scale` FLIP 过渡到最终矩形，真实组件已处于最终布局且只做透明度进入。动画不参与事务结果。

新的显隐调用必须在第一次异步让出执行权之前完成第 1～5 步，因此快速操作会按调用顺序读取最新状态，不会发生覆盖更新。显隐、长按换位和七组件尺寸切换复用同一分层 Auto Layout 动效；新重排开始时立即取消并清理上一次动画。`scaleX/scaleY` 只允许出现在无内容的临时外壳上，真实组件、文字、图片和控件始终按最终尺寸绘制。系统开启“减弱动态效果”时不创建临时外壳且关闭过渡。

### 后台工作生命周期

`hidden` 不能等同于“没有绘制成本”。显隐状态通过 `notch:home-modules-changed` 同步给现有后台工作：

- 音乐 WebGL 效果在音乐组件隐藏时取消 RAF，不允许只在每帧判断后继续申请下一帧；恢复时按需重启。
- 当前窗口组件隐藏后，停止 6 秒一次的窗口扫描；恢复且首页展开时立即刷新一次。
- 镜子隐藏时同步执行 `stopMirror()`，不等待任何动画。
- 快速录音处于 `recording / paused / saving` 时不能从首页移除；已经隐藏时，录制页仍可正常开始、暂停和停止录音。
- 番茄钟属于持续业务状态，隐藏后继续计时和到期提醒，但不需要执行只为可见效果服务的动画。
- 笔记、常用指令及其他隐藏组件不清数据，也不执行仅为展示服务的刷新。

## 设置页交互

在设置页新增独立的“首页组件”卡片，与现有“显示功能”分开。现有“显示功能”控制顶层 Tab；“首页组件”只控制首页七个卡片。

每一行包含组件名称、简短说明和开关。切换成功后立即更新首页布局并显示状态提示。关闭最后一个开关时：

- 不修改 LocalStorage；
- 开关恢复为开启；
- 提示“首页至少保留一个组件”。

开关的 `checked` 值始终从 `renderer/app.js` 的单一状态源重新渲染，不把事件触发时的 DOM 值当作事实来源。快速连续操作、同一组件反复开关和失败回滚后都必须重新同步七个开关。显隐操作提交期间只禁用当前开关；因为状态提交是同步事务，其他开关随后发起的操作会读取到最新状态。

状态快照同时包含 `persisted`。一旦写入失败，该值保持 `false`，直到后续一次成功写入完整当前隐藏集合；期间任何被拒绝的操作都不得把它伪装回 `true`。设置卡片持续显示“仅当前会话”，而不是只闪现一次 Toast。

资源相关规则：

- 隐藏镜子时立即调用现有 `stopMirror()`，释放摄像头 Track、视频源和镜面动画帧。
- 快速录音进行中时，其隐藏开关禁用并显示“录音进行中”；录音结束后恢复可操作。
- 快速录音已经隐藏时，录制页仍可正常开始录音；首页显隐不能被误用为录音功能总开关。
- 隐藏其他组件只改变呈现，不清除笔记、指令、计时或窗口隐藏状态。

## 数据流与接口边界

显隐设置完全属于当前渲染页面的本地工作区状态，不新增主进程 IPC：

```text
设置页开关
  → 基于最新状态纯函数校验候选显隐变化
  → 纯函数求解并验证候选完整网格
  → 必要时同步释放资源
  → 同一任务内提交内存状态与全部 DOM 矩形
  → 写入 notch-home-hidden-modules-v1
  → 派发 notch:home-modules-changed
  → 最终布局做可取消的轻量淡入
```

`renderer/domain.js` 提供纯函数：

```js
normalizeHiddenHomeModules(value, moduleIds)
updateHomeModuleVisibility(hiddenIds, moduleIds, moduleId, visible)
resolveHomeWidgetLayout(order, sizes, hiddenIds, columns, rows)
validateHomeWidgetLayout(layout, visibleIds, columns, rows)
layoutVariantForPlacement(placement)
```

`renderer/app.js` 负责 LocalStorage、候选布局预验证、原子布局应用、动效和镜子释放，并对外只暴露只读快照、`isVisible(id)` 和显隐事务方法。设置页复用同一状态，不建立第二份缓存。Portable workspace 现有的 LocalStorage 快照机制会自动包含新增键。

### 事务结果矩阵

| 分支 | 内存 / DOM | LocalStorage | 开关与反馈 |
| --- | --- | --- | --- |
| ID 或参数无效 | 不变 | 不写 | 恢复事实状态，提示未更新 |
| 请求值已经满足 | 不变 | 不写 | `changed: false`，不重复提示 |
| 试图隐藏最后一个组件 | 不变 | 不写 | 开关弹回，播报至少保留一个 |
| 活动录音时从可见改为隐藏 | 不变 | 不写 | 录音开关保持开启并说明原因 |
| 候选布局无效 | 不变 | 不写 | 恢复事实状态，提示原布局已保留 |
| DOM 应用异常 | 恢复操作前布局 | 不写 | 提示布局已恢复；镜子不自动重启 |
| DOM 成功、存储失败 | 新布局生效 | 保留旧值 | 持续显示“仅当前会话” |
| 全链路成功 | 新布局生效 | 写入完整隐藏集合 | 七个开关同步并提示成功 |
| 启动时存储损坏 | 安全规范布局 | 尝试写回规范值 | 写回失败时持续显示“仅当前会话” |
| 启动时布局引擎异常 | 全部可见只读安全布局 | 原值不动 | 七个开关全部开启且禁用，显示安全模式 |

所有分支都有唯一、可观察的最终状态，不存在“页面变了但开关没变”“提示成功但未保存”或“失败后留下半套网格”的中间态。

## 错误与恢复

- LocalStorage 读取或内容规范化失败：恢复全部组件可见并尝试写回安全规范值；修复写入仍失败则进入“仅当前会话”状态，但不影响其他首页数据。
- LocalStorage 写入失败：当前会话仍可使用新布局，状态快照持续标记 `persisted: false`，直到下一次完整写入成功。
- 初始化时布局求解器返回无效结果：用默认顺序、默认尺寸、全部可见生成只读安全布局，保留原存储不覆盖；设置页显示七个全部开启但禁用的“安全模式”有效状态，并输出可诊断错误，不能让开关与实际画面互相矛盾。
- 用户操作时候选布局求解或验证失败：整个事务回滚；内存、DOM、开关和 LocalStorage 均保持操作前状态。
- 原子 DOM 应用发生意外异常：用操作前已经验证的布局立即恢复全部矩形和内存显隐状态，不写 LocalStorage、不派发成功事件；若该操作曾尝试隐藏镜子，摄像头保持关闭并显示静态封面，隐私安全优先于自动重启。
- 录音状态在切换瞬间发生变化：显隐事务同步读取最新录音状态；若已开始录音则拒绝隐藏。事务提交不等待动画，因此不存在动画等待窗口。
- 组件恢复后内部资源加载失败：显示该组件既有空态，不影响整体布局。
- 快速连续切换：每次调用都在首次异步让出前完成验证和状态提交；后一次调用必须读取前一次的新状态。淡入动画使用代次号或 Animation 引用取消旧实例，不能反向覆盖最终状态。

## 测试策略

### 纯函数测试

穷举七个组件的全部 127 种非空显隐组合。每个结果检查：

- placements 的组件集合与可见集合完全相等；
- 每个矩形宽高为正整数；
- 坐标在 `12 × 4` 内；
- 48 个单元格每格恰好被覆盖一次；
- 任意两个矩形不相交；
- 输入 order、sizes、hiddenIds 未被修改；
- 五组件主组件选择遵守偏好和顺序；
- 最后一个组件不可隐藏；
- 损坏存储恢复为安全默认值；
- 布局验证器拒绝缺项、重复项、零尺寸、非整数、越界、交叠和未覆盖满 48 格的结果；
- 显隐 reducer 连续执行时不丢更新，输入对象均不被修改。

### Electron 几何验收

在实际渲染页面中验证 1～7 个组件的代表组合，并分别覆盖标准窗口 `1240 × 616` 与主进程可能收缩到的窄窗口 `1000 × 576`：

- 可见组件矩形不相交且全部在 `.home-bento` 内；
- 每个可见的主要按钮、输入区、图片、视频和滚动容器都在所属组件边界内；
- 隐藏元素不可聚焦、不可点击；
- 自动填充模式下尺寸按钮隐藏、不可聚焦，恢复七组件后重新可用；
- 镜子隐藏后视频 `srcObject` 为空；
- 正在录音时录音组件开关不可关闭；
- 录音组件隐藏后，录制页开始、暂停、停止录音仍然有效；
- 连续隐藏不同组件得到隐藏集合并集，同一组件连续关开以最后一次操作为准；
- 注入无效候选布局时，DOM、LocalStorage 和设置开关均不改变；
- 模拟 LocalStorage 写入失败时，当前会话布局生效且出现“仅当前会话”提示；
- `prefers-reduced-motion` 下不创建 Auto Layout 临时外壳，也不产生布局过渡；正常模式下只有无内容外壳允许缩放，真实组件动画关键帧不得包含 `scale`。

### 组件内容契约验收

仅检查组件外框不够，文字仍可能压住按钮。对七个组件在五种 `data-layout-variant` 下建立保护区契约：

- 音乐：标题区与控制区不相交，三枚控制按钮都在容器内。
- 番茄钟：读数、开始/暂停和重置控件不相交，数字输入不被裁切。
- 快速录音：头部、转写区和三枚控制按钮垂直分区，控制区不得缩放。
- 当前窗口：标题栏固定，窗口列表只在自身区域滚动。
- 镜子：舞台填满组件，图片和视频保持等比 cover。
- 随笔记：工具栏固定，只有正文区域滚动，保存按钮始终可见。
- 常用指令：标题和输入框固定，只有指令列表滚动。

对 DOM 矩形做边界与保护区相交测试，并对 1～7 可见数各保存一张人工验收截图。交互控件边界测试不能替代这组内容契约。

### 生命周期与功耗验收

- 音乐隐藏后 WebGL RAF 停止，恢复后只启动一个 RAF 链。
- 当前窗口隐藏后跨越两个 6 秒周期都不调用窗口枚举，恢复后恰好主动刷新一次。
- 番茄钟隐藏超过一秒后剩余时间继续减少，到期提醒不丢失。
- 镜子隐藏操作不等待动画，摄像头 Track 同步进入 `ended`，`srcObject` 立即清空。
- 显隐操作不得新增未清理的计时器、事件监听器或 Animation 实例。

### 人工视觉验收

分别查看 1～7 个可见组件的最终布局和七组件 × 五版式内容契约，重点检查音乐、番茄钟、录音、镜子和笔记在 `wide / tall / full` 版式下的文字截断、控件距离、图片裁切与滚动行为。任何组件内部重叠、非等比拉伸、按钮被裁掉、后台资源未停或首页留白都视为阻断发布的问题。

## 对抗性走查结论

| 攻击场景 | 原方案风险 | 修订后的封口 |
| --- | --- | --- |
| 连续快速关闭两个组件 | 等待淡出期间两个操作读取同一旧状态，后提交者覆盖前者 | 状态事务在首次异步让出前同步提交；动画只是结果，不参与提交 |
| 重复发送当前已满足的显隐值 | 无意义重排、写盘或错误触发录音守卫 | 返回 `changed: false` 的幂等成功，不产生任何副作用 |
| 关闭镜子同时淡出 | 摄像头可能多存活一个动画周期 | 候选布局验证后立即 `stopMirror()`，再更新 DOM |
| 隐藏组件后调整其他组件尺寸 | 容量归一化可能暗改隐藏组件偏好 | 任何隐藏状态都进入自动填充模式并关闭尺寸切换 |
| 只给 DOM 加 `hidden` | 音乐 RAF 和窗口扫描仍持续耗电 | 显隐事件驱动资源暂停/恢复，番茄钟按业务语义例外继续 |
| 音乐效果恢复时重复申请 RAF | `restart()` 与 `draw()` 各申请一帧，形成无法完整取消的双链 | 只允许 `draw()` 作为唯一调度点，暂停后 RAF ID 必须为 0 |
| 求解器产生部分或交叠布局 | DOM 可能写到一半才发现错误 | 纯验证器先检查集合、整数、边界、交叠和 48 格完整覆盖 |
| 注册表与首页 DOM 缺项或重复 | 逻辑布局通过但真实页面仍会出现空洞 | 启动前校验七个 DOM ID 与固定注册表完全一致，不一致直接失败 |
| 初始化布局故障 | 自动清空用户显隐设置会造成不可逆偏好丢失 | 只渲染默认安全布局，不覆盖原存储，并禁用显隐操作 |
| 一次写入失败后又发生被拒绝的操作 | 返回值可能错误宣称当前状态已持久化 | 独立维护会话 `persisted` 脏标志，只有完整写入成功才能恢复 |
| 录音组件隐藏后从录制页启动 | 把首页显隐误当成功能总开关，破坏录制页 | 录制页继续可用；只禁止在活动录音过程中执行“从可见变隐藏” |
| 外框无交叠但内部文字压住按钮 | 原几何测试无法发现 | 增加七组件五版式保护区契约和人工截图矩阵 |
| 窄屏上同一逻辑模板物理尺寸变小 | 标准 1240 宽通过但真实小屏裁切 | 同时验收 `1240 × 616` 和 `1000 × 576` |

关键设计决策及被否决方案记录在 `docs/adr/0002-home-widget-gapless-layout.md`。

## 验收标准

- 设置页可以隐藏和恢复七个首页组件，且至少保留一个。
- 127 种非空组合均通过零空洞、无重叠、无越界测试。
- 显隐变化不修改 `notch-home-order-v3` 和 `notch-home-widget-sizes-v2`。
- 所有组件内部元素无重叠、无异常变形，交互控件始终可用。
- 隐藏镜子立即释放摄像头；录音中不能隐藏快速录音。
- 隐藏音乐或当前窗口后，其纯展示 RAF 或窗口扫描停止；番茄钟业务计时不中断。
- 恢复组件后数据、顺序和尺寸偏好仍在。
- 快速连续切换、无效布局和存储失败分别满足顺序一致、完整回滚和明确降级提示。
- 支持系统“减弱动态效果”。
- `npm test` 全部通过；不执行打包或发布。

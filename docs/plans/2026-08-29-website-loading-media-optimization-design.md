# 官网 Loading 与媒体优化设计

## 目标

首屏的石板与 Mac 不受后续媒体阻塞。Mac 屏幕内部承担一段自动播放的“开机/唤醒”动画，同时后台准备第二屏截图和第一个 TAB 录屏。用户不需要滚动或操作鼠标。

## 时序

首屏状态分为 `loading`、`revealing`、`ready`：

- `loading`：Mac 屏幕保持黑底，中央圆角壁纸蒙版在 `62% × 54%` 与 `84% × 76%` 两档尺寸间以 1.6 秒完整周期呼吸，内部壁纸同步做幅度更明确的反向推拉；标题、面板、描述和下载按钮隐藏。即使媒体已在本地缓存中，动画也至少展示 2.4 秒。
- `revealing`：六张第二屏 WebP 与首个 MP4 可播放且最短展示时间已满足，或 8 秒超时。Loading 文案先淡出，小窗描边、高光和阴影立即移除；扩张期间底层全屏壁纸保持隐藏，避免两张不同裁切比例的壁纸在圆角边缘产生接缝。小窗真正铺满后底层壁纸才无缝接管，并始终继承真实屏幕圆角。
- `ready`：壁纸无缝接管屏幕，再依次显示标题、导航、真实面板、描述和下载按钮；面板入场结束后才允许点击折叠。

启用 `prefers-reduced-motion` 时跳过持续呼吸和等待，直接进入完整首屏。状态只允许从 `loading` 前进一次，迟到的超时或媒体事件不得让首屏回跳。

## 媒体策略

- 六段 990 × 640、10fps 的 GIF 转为无声 H.264 MP4，使用 `yuv420p` 与 `faststart`，保留循环播放。
- 六张第二屏大幅 PNG 转为 WebP，同时作为 TAB 视频 poster 和视频失败回退。
- 首屏摄影素材继续使用已压缩 JPG；需要透明通道的折叠面板、图标与 SVG 遮罩保留原格式。
- 页面只挂载当前 TAB 与下一个 TAB 的视频，其余位置显示中性占位；首个视频由首屏预加载器使用 `preload=auto` 提前准备。

## 验收

- 首屏石板与 Mac 立即可见，Loading 动画严格裁切在屏幕内。
- 正常加载与 8 秒超时均能进入完整首屏，且不会在稍后回跳。
- 六个 TAB 使用 MP4，首个可自动静音播放，失败时显示真实 WebP 封面。
- `npm test`、`npm run lint`、`npm run build:pages` 通过，并在浏览器中确认无控制台错误。

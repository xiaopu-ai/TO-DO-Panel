# ADR-0002：首页组件使用有限模板与原子显隐事务

## Status

Accepted

## Context

TO-DO Panel 首页是固定 `12 × 4` 网格，现有七个组件的偏好尺寸面积总和恰好为 48。用户希望隐藏不需要的首页组件，同时明确要求其他组件自动补位，不能出现留白，也不能使组件内部元素重叠或变形。

这不是单一 CSS 可见性问题。显隐操作同时影响：

- LocalStorage 中的用户偏好；
- 首页顺序和尺寸偏好的兼容；
- 1～7 个组件的完整空间分配；
- 音乐 WebGL、窗口扫描、镜子摄像头和番茄钟等不同生命周期；
- 快速连续切换、存储失败和布局异常时的一致性；
- 标准窗口与窄屏窗口中的内容完整性。

系统是单窗口、本地 Electron 应用，组件集合当前固定为七个。设计重点是确定性、低功耗和可穷举验证，不需要面向任意第三方组件扩展。

## Decision

1. 用新增的 `notch-home-hidden-modules-v1` 保存固定注册表中的隐藏 ID，不删除 DOM 或业务数据，也不修改既有顺序和尺寸键。
2. 可见数 1～6 使用六个有限、完整覆盖 `12 × 4` 的模板；七个全部可见时继续使用现有偏好尺寸打包器。
3. 引入纯布局验证器，在写 DOM 前检查 ID 集合、整数坐标、边界、交叠和 48 格完整覆盖。
4. 七组件全部可见时允许调整偏好尺寸；存在隐藏组件时进入自动填充模式并关闭尺寸切换，避免无效操作和隐藏偏好被容量归一化算法暗改。
5. 显隐操作使用同步、幂等的原子事务：基于最新状态生成候选、求解并验证、释放必要资源、提交内存与 DOM、持久化、派发事件。已满足的绝对请求无副作用；动画不参与提交，也不允许在提交前等待。
6. 显隐、长按换位和七组件尺寸调整保留可取消的 Auto Layout 连续动效：状态先同步提交，真实组件直接按最终矩形排版并只做透明度进入；另建不含子元素、不可交互的临时卡片外壳执行 `translate + scale` FLIP。新重排取消并清理旧外壳，`prefers-reduced-motion` 下完全跳过。
7. 显隐事件同时驱动后台生命周期：隐藏音乐停止 WebGL RAF，隐藏当前窗口停止周期扫描，隐藏镜子立即释放摄像头；番茄钟继续业务计时。
8. 首页快速录音的显隐不等同于录制功能开关。活动录音期间不能把卡片从可见改为隐藏，但已经隐藏时录制页仍可独立工作。
9. 初始化布局异常时渲染默认只读安全布局，不覆盖用户存储；用户操作产生无效候选布局时完整回滚。存储失败通过持续的 `persisted: false` 脏状态呈现，只有完整当前状态成功写回才能清除。

## Consequences

### Positive

- 所有 127 种非空显隐组合都能穷举证明无空洞、无交叠和无越界。
- 显隐操作不会通过真实内容缩放满足外层尺寸；只有不含内容的临时外壳参与几何过渡，符合组件内部不变形约束，同时保留原有 Auto Layout 手感。
- 同步提交消除了动画等待窗口中的并发丢更新和资源延迟释放。
- 自动填充模式与偏好尺寸模式边界清楚，不会出现“点了尺寸但没有效果”的伪交互。
- 隐藏组件会停止无意义的展示工作，符合常驻工具对功耗的要求。
- 状态、DOM、设置开关和持久化之间有明确的成功、回滚与降级语义。

### Negative

- 1～6 个组件时用户不能自由调整单个卡片尺寸，只能接受确定性模板。
- 七个组件需要分别适配五种内部版式，CSS 和视觉验收矩阵明显增加。
- 音乐效果和窗口扫描必须接入显隐生命周期，范围不再局限于布局代码。
- 初始化布局故障需要只读降级状态和错误提示，增加少量状态管理复杂度。

### Neutral

- 隐藏列表使用固定注册表顺序序列化，不随用户拖拽顺序变化。
- 五组件模板仍用保存的尺寸偏好和顺序决定左侧主组件，但不会写回偏好。
- 番茄钟隐藏后继续计时，因为它是业务状态而不是纯展示效果。

## Alternatives Considered

### 只给组件添加 `hidden`

拒绝。剩余组件保留原网格面积，必然出现空洞；后台 RAF 和窗口扫描也可能继续运行。

### CSS Grid `auto-flow: dense`

拒绝。它只能尽量填洞，无法保证任意组件面积组合精确覆盖 48 格，也不能稳定控制五组件主次关系。

### 通用 Masonry 或矩形装箱算法

拒绝。七组件固定场景不需要通用复杂度；结果随顺序和尺寸变化，难以提供稳定视觉和穷举验收。

### 自由拖拽调整边界

拒绝。会把问题扩大为约束编辑器，还需要处理最小尺寸、冲突消解、键盘操作和持久化迁移，不符合当前用户诉求。

### 使用 `transform: scale()` 保持旧内部布局

拒绝。文字、图片和控件会被拉伸，动画期间也会增加 GPU 合成负担，直接违背“不重叠、不变形”。

### 先淡出旧布局，再异步提交新状态

拒绝。快速切换时多个操作会基于同一旧状态计算并互相覆盖，镜子和录音还会多出一个资源竞态窗口。

### 隐藏状态下继续允许尺寸调整

拒绝。有限模板可能让尺寸按钮没有可见效果；现有 48 格容量归一化还可能修改隐藏组件的偏好，破坏数据无损原则。

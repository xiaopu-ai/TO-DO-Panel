# 架构与 UI / 性能审查（2026-11-10）

本轮已改的内容见 git diff；这里只记录**审查发现但尚未处理**的问题，按影响排序。

## 架构

- `main.js` 约 3800 行，是一个持有 40+ 个模块级可变状态的单文件：窗口状态机、提醒队列、剪贴板、转写 WebSocket、密钥库、链接抓取、待办收件箱全在一起。本轮只把新增能力放进了 `main/`，旧代码未拆。建议按「窗口 / 岛 / 剪贴板 / 转写 / 密钥 / 收件箱」逐个迁出，每个模块只导出 `start/stop` 与 IPC 注册。
- 渲染层 `app.js`（3900 行）+ `workspace.js`（2700 行）+ `styles.css`（5400 行）同样是单文件；所有 Tab 在启动时全部构建，没有按需加载。
- 主面板 preload 向同一个页面暴露了全部 80 个 IPC（含密钥、文件读写）。岛与权限窗口已改用各自的最小 preload，主面板未动。
- 系统能力依赖 `osascript`（窗口枚举、图标、前台应用、汽水音乐、粘贴），每次调用都是一次进程启动。真正的解法是一个常驻的原生 helper，这与已被推翻的 ADR 0001 不同：只做服务层，不重写界面。
- `main-services.js` 里的 `screenRecordingProbePolicy` 已无调用方（权限窗口直接读系统状态）。

## 性能（实测后的结论）

用 150 篇笔记、160 个链接、100 条待办的数据量，在 120Hz 屏上量主线程帧间隔：

- 展开 / 收起：约 110 帧里最多 1 帧超过 20ms（最长 19–31ms），首次展开一帧 44–50ms。
- 把面板固定在展开尺寸以避免整页重排：试过，前后数字没有差别，已撤回，不值得为它增加复杂度。
- 列表悬停效果：每次 `pointermove` 0.04–0.14ms，240 帧里 0–2 帧超过 12ms，不是问题。

结论：卡顿的主因是每次展开前等待 osascript（已修）。下面几项只在特定操作时出现，未量化、未处理：

1. 展开 / 收起在全窗口伪元素上过渡 `clip-path`，上面还有一层 mask 合成的锥形渐变描边。主线程量不到合成器开销，需要用 Performance 面板确认。
2. 镜子的液态悬停：鼠标离开后 `feTurbulence` 滤镜还要逐帧衰减约 2 秒。
3. 录音可视化在面板折叠或切到别的 Tab 时仍以 60fps 跑带 `context.filter = blur()` 的绘制。
4. `windows:list` 每次都把所有图标的 base64 随结果一起过 IPC。

## UI / 交互（未处理）

- 删除撤销已补（指令、链接、分组、录音、密钥、笔记、待办批量）。退出应用前会先把撤销窗口内的删除执行掉（最多等 0.8 秒）。
- API 设置对话框标了 `aria-modal` 但没有焦点陷阱，背后的面板也没有 `inert`（本轮只补了 Esc 关闭与焦点归还）。
- 日期弹层：月份箭头 20×20；过去的日期可点、点完才报错；触发按钮缺 `aria-expanded`。
- 密钥行内操作按钮命中区约 21px（其余文字按钮已补到 24px）。
- 截断文本没有 `title`：链接、录音、密钥、笔记列表行。
- `#credential-password` 是 `type="text"`，没有显示 / 隐藏切换。
- 重复声明：91 个选择器被原样重复（`.topbar` 4 次、`.home-pomodoro` 组 4 次），合并会改变层叠顺序，未动。
- 硬编码：146 处字号、287 行字面颜色（49 种十六进制值、38 种白色透明度）、36 种圆角值；成功绿 4 种、错误红 7 种、蓝 6 种以上，各应收敛为一个 token。
- 减弱动态效果：WAAPI 动画（密钥展开）与 JS 驱动的动效（Dock 放大、镜子水波）未受 `prefers-reduced-motion` 约束。

## 产品链路走查（二阶问题，已处理）

- 音乐写死汽水音乐 → 自动识别 7 种播放器，可切换，Apple Music 兜底。
- 新用户装完打开后屏幕上什么都没有（无 Dock 图标、折叠条藏在刘海里）→ 首次启动必显示一次引导窗口，带用法说明。
- 监控默认开启后，每个几秒钟的问答回合都会从刘海弹提醒 → 只对 30 秒以上的回合提醒。
- 缺辅助功能权限时点音乐 / 粘贴，系统授权提示会被别的窗口盖住 → 改为打开自己的权限窗口。
- 岛的耳朵比折叠条宽，悬停在耳朵上按空格唤不出面板 → 已纳入悬停范围。
- 面板收起期间开 / 关了播放器，组件状态过期 → 每次展开重新识别。
- Claude 的上下文上限是推断值却显示得像事实 → 明细里标成「约」。

仍然存在、未处理的二阶问题：

- 媒体键由系统路由给当前的 Now Playing 应用：如果浏览器里正放着视频，按键可能落到浏览器而不是所选播放器。
- 岛的耳朵会盖住紧贴刘海的菜单栏项（菜单特别多的应用）；目前只能在托盘里整体关掉。
- 「必需权限」是固定的两项，不随用户实际启用的组件变化：不用「当前窗口」和音乐的人也会被要求授权，只能勾「不再自动显示」。
- 用户正盯着 Claude / Codex 窗口时完成提醒仍会弹出。
